# ADR-0005: Config Registry

Status: Accepted 2026-10-24 · Date: 2026-10-06

## Context
Like UCR, we need one typed place for node configuration, rendering of config files owned by modules, and
reliable reload hooks. Domain-wide defaults come from policies; local overrides and emergency forced values
must win.

## Decision
1. **Keys** are declared by module manifests:
   - name: dotted, owned by a module prefix, e.g. `dhcp.dhcp4.interfaces`
   - Zod schema, default, description key (i18n)
   - `secret: false` always. Secrets never go into the registry; they're referenced by secret id instead.
2. **Layers** in ascending precedence: `default` (manifest) < `domain-policy` (computed from directory policies
   linked to the node's OU chain, cached in `/var/lib/opendc/registry/policy-cache.json`) < `local`
   (`/etc/opendc/registry/local.json`) < `forced` (`/etc/opendc/registry/forced.json`). Every read can explain
   which layer supplied a value (`opendc registry get --explain key`).
3. **Templates** are pure TypeScript functions `(view: RegistryView, ctx: TemplateContext) => string`, owned
   by modules, and declare which keys they read. There's no template engine. Each output starts with a header
   made by the registry:
   `# Generated by OpenDC (module <id>, template <tpl>). DO NOT EDIT – changes will be overwritten. See: opendc registry explain <fileId>`.
   The comment syntax is per file type.
4. **Managed files** are identified by `fileId`, not by path. The `fileId → path, owner, mode, comment style`
   mapping is compiled into the agent allowlist at build time. Paths come from the OS adapter, so the same
   fileId can map to different paths on Debian and RHEL.
5. **Commit:** a change set computes the affected templates (from their declared keys), renders them, and
   sends changed outputs (by content hash) to `agent:file.writeManaged`. The write is atomic: temp file,
   fsync, rename, and a backup of the previous version. Then the declared handlers run in a stable order
   (`service.reload`/`restart`, or a module's agent operation). A failed handler rolls the files back and
   reports an error.
6. **Drift detection:** a diagnostic compares each managed file's hash with the last rendered hash and flags
   manual edits.
7. The registry is a library used by `opendc-api` (API and CLI writes) and `opendc-watcher` (policy changes).
   Concurrent commits are serialised with a lock file under `/run/opendc`.

## Consequences
- No templating dependency, and templates are type-checked and unit-testable.
- Domain-policy values keep working when the DC is unreachable, because they're cached.
- Templates are TS functions, so a template change needs a platform release. That's intended: there's no
  runtime code injection.

## Alternatives
- **UCR-style text templates with embedded Python/JS:** a runtime code execution surface.
- **Handlebars/EJS:** a dependency with weaker typing.
